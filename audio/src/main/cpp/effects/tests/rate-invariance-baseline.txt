# Efectos que entregan NIVELES DISTINTOS segun el sample rate, medido por
# `RateInvariance.EveryEffectDeliversTheSameLevelAtEveryRate`.
#
# La propiedad: el mismo seno de 440 Hz a 44,1 / 48 / 96 kHz tiene que salir con
# el mismo RMS, dentro de 0,5 dB. Es una propiedad DEBIL a proposito —dice que
# suena igual de fuerte, no que suene igual— pero es la unica que aplica a los
# 23 efectos, porque un reverb no tiene "cutoff" que medir.
#
# ESTO ES UN TRINQUETE, NO UNA LISTA DE EXCEPCIONES. El test falla si:
#   - un efecto que NO esta aca empieza a fallar  (deuda nueva), y TAMBIEN
#   - un efecto que SI esta aca deja de fallar    (deuda pagada: borrar linea)
#
# Formato:  <EFFECT_TYPE> | <desviacion medida> | <de donde sale>
#
# ---------------------------------------------------------------------------
# LA MEDICION SEPARO DOS POBLACIONES, NO UN GRADIENTE. De los 21 efectos
# medibles, 16 quedaron por debajo de 0,02 dB y 18 por debajo de 0,25. Los cinco
# de abajo arrancan en 0,94. No hay nada entre 0,25 y 0,94, asi que el corte en
# 0,5 dB no es una eleccion de tolerancia: es donde la propia medicion partio.
#
# ESTA ES LA DEUDA DE LA CLASE DE WD-3.4 EN LA CAPA DE EFECTOS. WD-3.4 mira
# `SynthEngineDispatcher`, que prepara dieciseis engines con `prepare(48000,
# 4096)` literal. Lo de aca es el mismo error escrito de otra forma: estado
# interno dimensionado en SAMPLES contra un rate que no es el vigente.
# ---------------------------------------------------------------------------

DECI_HPF       | 5,87 dB | el `step = fs / target` del sample-and-hold cambia con el rate, y con el la cantidad de aliasing que entra
SHIMMER_REVERB | 5,20 dB | el desplazador de pitch trabaja sobre una ventana en samples
PLATE_REVERB   | 3,53 dB | largos de la red FDN dimensionados en samples
HALL_REVERB    | 1,97 dB | misma FDN que plate, mismo origen, menos severo
CABINET        | 0,94 dB | la IR del gabinete es una tabla de N muestras; a 96 kHz representa la mitad del tiempo, o sea el doble de frecuencia

# NO estan aca, y por que:
#
#   RANDOM_RESO — no es medible, no es deuda. Sortea un LFO `RANDOM_SMOOTH` y
#   `LFO::randomFloat()` siembra con `std::random_device`, asi que dos instancias
#   recien construidas ya difieren. Medido: dispersa 28,9 dB entre corridas al
#   MISMO rate, contra los 0,5 dB que este barrido tolera. El instrumento no
#   puede resolver lo que se le pediria afirmar, y por 32 veces.
#
#   EL CRITERIO DE EXCLUSION, ESCRITO PARA QUE NO SE VUELVA A APLICAR MAL:
#   un efecto queda fuera cuando su dispersion corrida-a-corrida es comparable a
#   la TOLERANCIA DEL BARRIDO (0,5 dB) — NO cuando es comparable a su propia
#   diferencia entre rates. Son dos preguntas distintas y sonaban igual.
#
#   TAPE_ECHO estuvo excluido de aca por la segunda, que es la equivocada
#   (REQ-005 S1). Su premisa era CIERTA y hasta conservadora: 500 muestras por
#   rate dan 0,0515 dB de dispersion corrida-a-corrida contra 0,0517 dB entre
#   rates, o sea que efectivamente NO se puede resolver esa diferencia. Pero el
#   barrido nunca pidio resolverla: pide que el nivel no se mueva mas de 0,5 dB,
#   y contra ese umbral el margen es de 15,3 sigma. Un criterio de RESOLUCION
#   aplicado a un test de UMBRAL deja fuera del catalogo a un efecto que si se
#   podia medir — y encima lo reemplazaba por un test intermitente que fallaba 1
#   de cada 2.800 corridas.
#
#   Verificado al dejarlo entrar: 200 corridas del barrido, cero fallos (la
#   prediccion es P < 5e-7; una sola corrida verde no la distingue de P = 0,1).
