# Efectos que DIVERGEN a sample rates por debajo de 44,1 kHz, medido por
# `NyquistLimits.EveryDeclaredCaseStillReproduces`.
#
# La causa CONOCIDA —la de FILTER, la unica verificada— es una frecuencia acotada
# contra una CONSTANTE (20 kHz) y despues convertida a omega contra el sample
# rate VIGENTE. Cuando el rate baja, omega pasa de pi, sin(omega) se vuelve
# negativo, el alpha del cookbook RBJ cambia de signo y los polos salen del
# circulo unitario. Los otros seis casos NO estan diagnosticados: ver abajo.
#
# ESTO ES UN TRINQUETE, NO UNA LISTA DE EXCEPCIONES. El test falla si:
#   - un efecto que NO esta aca empieza a divergir  (deuda nueva), y TAMBIEN
#   - un efecto que SI esta aca deja de divergir    (deuda pagada: borrar linea)
#
# Misma semantica que `reset-baseline.txt` y `scripts/rt-safety-baseline.txt`.
#
# Formato:  <EFFECT_TYPE> | <rates que reproducen> | <por que>
#
# ---------------------------------------------------------------------------
# DUEÑO DE TODA ESTA DEUDA: **WD-3.5 — clamp de coeficientes contra Nyquist**.
# Poner `min(valor, 0,45 * fs)` donde falta retira las DOS entradas de FILTER, y
# nada mas: verificado por mutacion. Vaciar este archivo es mas trabajo que una
# linea, y por eso WD-3.5 quedo con el esfuerzo a re-estimar.
#
# UNA CORRECCION AL REQUERIMIENTO, MEDIDA: WD-3.5 dice que el escenario de falla
# es "cutoff a 20 kHz en un device a 44,1 kHz". **No reproduce.** A 44,1 kHz el
# omega queda en 0,907 pi con sin(omega) = +0,288 y la salida se mantiene en
# 1,088 de pico. El disparador real es cualquier rate por debajo de 40 kHz —
# entre ellos 32.000, que es un rate estandar de Android, y 16.000, que es el de
# un headset Bluetooth SCO. O sea: mas alcanzable que lo que decia el ticket, no
# menos.
# ---------------------------------------------------------------------------
