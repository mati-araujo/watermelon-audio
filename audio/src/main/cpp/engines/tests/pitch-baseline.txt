# Engines cuya FUNDAMENTAL se corre al cambiar de sample rate, medido por
# `EnginePitch.TheFundamentalDoesNotShiftBetweenSampleRates`.
#
# El criterio de WD-2.3.2: la misma nota tiene que sonar igual de afinada en un
# device que negocia 44,1 kHz y en uno que negocia 96. El umbral es 5 cents, que
# es donde un oido entrenado empieza a notar la diferencia.
#
# ESTO ES UN TRINQUETE, NO UNA LISTA DE EXCEPCIONES. El test falla si:
#   - un engine que NO esta aca empieza a correrse   (deuda nueva), y TAMBIEN
#   - un engine que SI esta aca deja de correrse     (deuda pagada: borrar linea)
#
# Misma semantica que `effects/tests/reset-baseline.txt` y
# `scripts/rt-safety-baseline.txt`.
#
# Formato:  <ENGINE> | <corrimiento medido> | <causa>
#
# ---------------------------------------------------------------------------
# VACIO. La unica entrada que tuvo —KARPLUS_STRONG, hasta 61 cents entre 44,1 y
# 96 kHz— se pago junto con el sintoma absoluto (118 cents bajo a 440 Hz sobre
# 44,1 kHz). Spread medido despues del arreglo: 0,07 a 0,39 cents sobre cinco
# notas y los tres rates.
#
# LA CAUSA DECLARADA ACA ERA FALSA, Y CONVIENE SABER POR QUE. Este archivo
# decia que el lazo sobraba `D ~= 7` muestras de "retardo de grupo del filtro
# del lazo mas el del interpolador". La cuenta no daba: el one-pole aporta 0,905
# muestras con el brillo por defecto y el interpolador lineal aporta CERO. De
# las 7 medidas, ~6 no eran del lazo — eran `smoothParam()` avanzando el
# suavizado UNA MUESTRA POR BLOQUE, que dejaba `brightness` en ~0,02 en vez de
# 0,5 durante todo el primer medio segundo.
#
# La firma que lo delata, y que ahora tiene test propio: el error dependia del
# TAMAÑO DEL BLOQUE (22,9 cents con bloques de 16, 126,3 con 1024). Un retardo
# de lazo no puede hacer eso.
#
# El 0,905 que si era del lazo se compensa con el retardo de FASE del filtro a
# la frecuencia pedida, no con el de grupo en DC — los dos coinciden cerca del
# default y se separan con la cuerda oscura, donde descontar el de DC dejaba la
# nota 16 cents ALTA.
# ---------------------------------------------------------------------------

# NO estan aca, y por que:
#
#   FM / SUPERSAW / WAVETABLE / GRANULAR — YA SE MIDIERON (2026-08-18), y por eso
#   no estan aca: los cuatro mantienen su fundamental entre los tres rates.
#   Spread medido sobre 110 / 220 / 440 Hz:
#
#       FM 0,07  ·  SUPERSAW 0,76  ·  WAVETABLE 0,01  ·  GRANULAR 1,14  cents
#
#   La prediccion que traia escrita este archivo era correcta y la razon tambien:
#   los cuatro derivan su incremento de fase contra el rate vigente en cada
#   bloque, asi que el modo de falla de Karplus-Strong —un LARGO en muestras
#   fijado una sola vez— no les aplica por construccion. GRANULAR, que era "el
#   candidato mas probable", tambien dimensiona sus granos contra el rate vigente.
#
#   PERO la medicion no salio gratis: destapo que FM y GRANULAR NO eran
#   bit-exactos entre tamaños de bloque, por un ulp que metia
#   `ParameterSmoother::processBlock()` con el parametro en reposo. Karplus no lo
#   mostraba porque sus defaults son 0,5 (potencia de dos, exacta en float).
#   Medir los que "seguro estaban bien" es lo que encontro el defecto.
#
#   SUPERSAW mide entre -2,6 y -3,6 cents respecto de la nota pedida, y eso NO es
#   deuda: son cuatro sierras desafinadas 15 cents por diseño, y la fundamental
#   agregada de un ensamble desafinado no tiene por que caer en el centro. Lo que
#   este archivo declara es invariancia entre rates, que si cumple.
#
#   SOUNDFONT — fuera del alcance del host: `SoundFontEngine` arrastra
#   tinysoundfont, que no compila en esta suite (ver el CMakeLists de este
#   directorio).
